# 엘림 · Global 장비 계산과 가방 동기화

엘림(1090)의 중국 본서버 1.5.4, 로직 빌드 594078 기준 장비 데이터입니다. 게임 DB와 도감 DB에 같은 데이터를 적용합니다. 중국 서버 출시일은 2026년 11월 5일, 글로벌 출시 일정은 11월 11일입니다.

| 항목 | 반영값 |
|---|---|
| 속성 및 아크 | 빛 · 고체 · 전용 아크 「연결음이 흐르는 동안」 |
| 기본 능력치 | 레벨 1 HP 1,270 · 공격력 83 · 방어력 75. 80레벨 최종 돌파 시 HP 15,392 · 공격력 660 · 방어력 909 |
| 장비 배치 | 5×5 판의 유효한 20칸. 권장 드라이브 7개 중 Ⅲ형 4개 |
| 장비 보너스 | Ⅲ형 한 개당 치명타 확률 +8%p. 인연 레벨 10 공격력 +5% |
| 전용 아크 | 정련 1~5단계 상시 공격력 +15%, +18.75%, +22.5%, +26.25%, +30% |
| 적용 기능 | 캐릭터 관리, 장비 감정·배분, 졸업 기준, 스킬·돌파 도감, 육성 재료 |

게임 내 스킬 계수와 실전 타격 시각은 서로 다른 입력입니다. 이 빌드에는 엘림의 스킬 피해 계수 35개와 4개 전투 스킬의 성장 자료가 들어 있습니다. 신호 세기 전환·교대 후 협동 공격의 타격 시간과 팀 버프를 포함한 DPS 사이클은 실측 전이라 팀 시뮬레이션과 사이클 기반 효율표에서는 엘림을 제외합니다. 원본 네이티브 캡처 구성 요소의 중국 1.5 / 글로벌 1.5 실게임 호환성은 별도 확인 대상입니다. 캐릭터·아크 이름은 4개 언어로 표시되며, 한국어 스킬 용어와 요약에는 자체 번역이 포함됩니다. 상세 설명에는 중국어 원문이 남아 있습니다.

## 원자료

- 캐릭터, 장비, 성장, 스킬, 아크 수치 및 배치판은 [CN 1.5.4 클라이언트 테이블](https://github.com/555me/NTEData/tree/fe531251f0c618796bf989cbc08dbdbf63055d76/DataTable)에서 가져왔습니다. 정규화한 SQL의 source_file과 source_row는 사용한 원본 경로·행 키·해시를 담습니다. 아크 정련 수치는 CT_ForkBuff의 선형 보간을 따릅니다.
- 오프라인 가중치는 프로그램이 기존에 사용하는 [이환 공방 weight-configs API](https://yh.zzzmap.com/api/open/game-character/weight-configs)의 2026-11-07 스냅샷입니다. 계정에서 편집한 가중치는 기존 저장 경로로 관리합니다.
- 초상화·기본 복장·아크 아이콘은 [중국 클라이언트 기반 엘림 도감](https://mygamewiki.com/gallery/characters/yeermu.html)의 게임 에셋입니다. 출시일은 [중국 본서버 공지](https://www.bilibili.com/opus/1266699440321724441)를 따릅니다.

## 빌드 및 검증

Windows x64 CPython 3.11.15로 기존 빌드 절차의 make_stage_g231.py를 실행하면 elyms_catalog.py가 원본 DB의 SHA-256을 검사한 뒤 새 스테이징 디렉터리에 cn_154_elyms.sql과 이미지를 반영합니다. 실행 파일 검증 시 네 번째 위치 인수로 새 스테이지의 _internal/data를 전달합니다. 이 빌드의 기본 빌드 명령은 build_tools/README.md에 있습니다.

프로젝트 의존성이 설치된 Python에서 아래 명령으로 스테이징 결과를 검증할 수 있습니다.

```powershell
python build_tools/verify_elyms.py <stage/_internal>
```

테스트는 앱의 실제 카탈로그 로더로 DB와 이미지 경로·해시를 검증하고, Qt로 엘림 이미지 3개를 읽어 크기를 확인합니다. 이후 임시 계정을 만들고 일반 배분 경로로 드라이브 7개와 카트리지 1개를 배치한 뒤, 저장한 사용자 가중치가 기본값 갱신 뒤에도 유지되는지 확인합니다.

### Global 2.3.6 시작 오류 수정

2.3.3~2.3.5에 포함된 엘림 전신 이미지 `character_arts/1090.webp`가 카탈로그의 PNG 형식 검사에 걸려 프로그램 시작을 중단시켰습니다. 2.3.6은 같은 RGBA 픽셀을 `character_arts/1090_art.png`로 저장하고 이미지 매니페스트를 다시 생성합니다. 릴리스 설치 파일 빌드에서도 실제 `read_role_catalog` 검증을 통과해야 합니다. 설치 프로그램은 기존 패키지의 해당 WebP 파일을 제거합니다.

### Global 2.3.5 네이티브 가방 동기화

2.3.4까지는 계산기 DB에 엘림이 등록되어 있어도 `nte-core.exe` 내부에서 엘림의 캐릭터 참조를 변환할 때 `native.inventory.page`가 `NATIVE_MAPPING_UNSUPPORTED`로 중단될 수 있었습니다. 2.3.5의 빌드 도구는 같은 CN 1.5.4 데이터에서 엘림 ID 1090 및 장비 배치 정보를 읽고, Core의 캐릭터 표와 장비 표에 추가합니다. 설치 시 Calc 폴더의 Core가 교체됩니다.

원본 설치 파일을 풀어 얻은 `_internal` 폴더와 새 스테이지의 Core를 아래 명령에 전달하면 Windows에서 합성 가방을 실제 Core에 입력해 결과를 비교할 수 있습니다. 게임이나 실계정 접속 없이 실행합니다.

```powershell
python build_tools/verify_elyms_native.py official231/app/_internal/nte-core.exe stage/_internal/nte-core.exe
```
